# Soft availability constraints and preferences in scheduling tools (state of the art, Sept 2026)

Scope note: all vendor help-centre domains (calendly.com, help.calendly.com, community.calendly.com, cal.com, docs.savvycal.com, changelog.savvycal.com, help.reclaim.ai, usemotion.com, support.google.com, learn.microsoft.com, notion.com, vimcal.com), plus news.ycombinator.com, trustpilot.com, paulgraham.com, arxiv.org and hci.stanford.edu were blocked by the network egress proxy during this research. Findings below from those domains are taken from search-engine snippets of the pages (URL given), not from full-page reads; GitHub issue pages were read in full. Where a claim could only be verified by reading a blocked page, it is listed under Gaps rather than asserted. "Official" = vendor doc/blog; "User report" = forum, review site, GitHub issue or third-party review.

## KQ1. What availability controls do the main tools offer (per-event-type hours, buffers, minimum notice, per-day/week caps, date ranges, ranked/preferred slots, custom schedules, holidays, multi-calendar conflicts, batching, back-to-back limits, travel time)?

### Takeaway
Every booking-link tool now covers the "hard" basics (per-event-type schedules, buffers, minimum notice, per-day/week/month caps, date-range windows, multi-calendar conflict checks, date-specific overrides). Only SavvyCal exposes a first-class *soft* preference (ranked schedules / highlighted preferred times) on the booking page itself; the AI calendars (Reclaim, Clockwise, Motion) express preferences as goals and priorities that the tool enforces by moving things, not as booking-page semantics. No mainstream tool ships "only book adjacent to existing meetings" batching; it exists only as an open Cal.com feature request (Dec 2025).

### Cited Findings

**Calendly (official)**
- Meeting limits: "choose how many times an event type can be booked per day, week, or month" and also "limit the total number of meetings booked through your entire account per day, week, or month" — [Calendly Help: How to set meeting limits](https://help.calendly.com/hc/en-us/articles/32130092291095-How-to-set-meeting-limits)
- Buffers: "A 30-minute meeting with 15-minute buffers before and after needs 60 minutes of free time"; community answers state the maximum buffer is 3 hours — [Calendly Help: How to use buffers](https://calendly.com/help/how-to-use-buffers); [Calendly Community thread on limiting to 1/day](https://community.calendly.com/how-do-i-40/how-do-i-limit-different-events-and-types-to-only-1-per-day-2164)
- Minimum notice: "The default minimum scheduling notice for all event types is 4 hours but it can be left blank" — [Calendly Help: fine-tune availability](https://calendly.com/help/how-to-fine-tune-your-availability-settings)
- Holidays: Calendly "can block off your availability for holidays based on your country … available on all plans"; supported countries are Australia, Brazil, Canada, France, Germany, Mexico, Netherlands, Spain, UK and US; "date-specific hours cannot override an active holiday. You must turn off a holiday block before adding availability for that day" — [Calendly Help: Holidays within Calendly](https://help.calendly.com/hc/en-us/articles/16083064244887-Holidays-within-Calendly)
- Calendar connections: free plan allows one connected calendar, paid plans up to six — [Calendly Community: free/busy status guide](https://community.calendly.com/asked-answered-79/calendly-calendar-availability-and-free-busy-status-guide-4885)
- Calendly Community (user report, thread #210): a user asked for a per-type weekly maximum and described wanting to "push people toward particular meeting slots … prefer meetings to happen in a block rather than scattered throughout the day", envisioning a page that marks one time as ideal and "rank[s] other options by priority" — [Calendly Community #210](https://community.calendly.com/how-do-i-40/add-rule-to-limit-set-maximum-number-of-meetings-of-a-type-per-week-210). (Calendly has since shipped per-type and account-wide limits, per the help article above; the ranking part remains unshipped as far as this research found.)

**Cal.com (official + GitHub)**
- Limits section of an event type supports frequency limits (N bookings per day/week/month/year) and duration limits ("only … a maximum of 10 hours booked per month"); multiple limits can be stacked ("up to 5 bookings per day but no more than 20 per week") and "the stricter limit at any given moment takes precedence" — [Cal.com blog: booking limits](https://cal.com/blog/booking-limits-frequency-duration-future); [Cal.com Help: Booking frequency](https://cal.com/help/event-types/booking-frequency)
- Cal.com also has an "Only show the first slot of each day as available" setting (referenced as an existing option by a Sept 2026 issue) — [cal.diy issue #30089](https://github.com/calcom/cal.diy/issues/30089)
- User-level (cross-event-type) booking limits exist in the v2 API — [Cal.com Docs: User booking limits](https://cal.com/docs/api-reference/v2/user-booking-limits)
- Bug report (user, 2023): "'Limit booking frequency' setting doesn't work" — [cal.com issue #10361](https://github.com/calcom/cal.com/issues/10361)
- Holidays: issue #8918 (opened 16 May 2023) complained that "While I can select the 'Holidays in xyz' calendar in Cal.com, it does not affect my availability" because holiday all-day events are free; the reporter added "Of course I could make an automation that duplicates holidays into another, user-owned calendar, but that feels backwards". Closed as resolved via PR #25561 — [cal.com issue #8918](https://github.com/calcom/cal.com/issues/8918)
- Availability overrides (vacation, OOO, one-off availabilities) tracked in issue #3239 — [cal.diy issue #3239](https://github.com/calcom/cal.diy/issues/3239)
- Batching / adjacency: issue #26187 "Adjacency-only booking", opened 24 Dec 2025 by marshallthomas47, proposes an event-type mode showing only slots that "Start immediately after existing busy events end, OR End immediately before existing busy events begin", with options for adjacency tolerance (0–30 min), filtering adjacent to "any busy event" vs "only meetings" (excluding focus blocks/personal events), and empty-day behaviour ("show no slots" or "allow the first meeting of the day"). Motivation: "batch all my meetings together to preserve large, uninterrupted blocks for deep work"; the author says Reclaim/Motion "maybe get me 60% of the way there". Status: open, labels Stale / feature / needs approval, no maintainer response — [cal.com issue #26187](https://github.com/calcom/cal.com/issues/26187)
- "Dynamic Slot Visibility / Look Busy" issue #30089 (2 Sept 2026): asks for "Maximum visible slots per day: X" that "should only affect what the customer sees … should NOT reduce the real availability", citing Bookem, HighLevel and OnceHub as already offering this; open, needs approval — [cal.diy issue #30089](https://github.com/calcom/cal.diy/issues/30089)
- Location-based availability requests: "Location-Based Availability" #17412 and "Allow different availability schedules for each event location" (virtual vs in-person at different times) — [cal.diy #17412](https://github.com/calcom/cal.diy/issues/17412); [CSCI-435 fork issue #17](https://github.com/CSCI-435-SE/cal.diy/issues/17)

**SavvyCal (official)**

- Buffers: "Buffer After: the minimum amount of time to keep open after a new event. Minimum Notice: the minimum amount of lead time required before the start of a new event" — [SavvyCal Docs: Configuring link availability](https://docs.savvycal.com/article/26-configuring-buffers)
- Time blocks: "define when you are available based on whether a specially named calendar event exists on your calendar" (naming conventions on calendar events open availability) — [SavvyCal Docs: Time blocks](https://docs.savvycal.com/article/27-time-blocks-to-define-availability)
- Per-day overrides — [SavvyCal Docs: Overriding availability on a specific day](https://docs.savvycal.com/article/23-overriding-availability-on-a-specific-day)
- Changelog: "Override improvements" let a link override apply "to all attendees or to a specific attendee" (previously always all attendees) and overrides became click-to-edit — [SavvyCal changelog: Override improvements](https://changelog.savvycal.com/override-improvements-319737); [SavvyCal changelog: Visible overrides](https://changelog.savvycal.com/visible-overrides-on-the-link-and-availability-editor-225625)

### Inferences
- The feature set has converged: caps, buffers, notice, windows, overrides and multi-calendar checks are table stakes across Calendly, Cal.com, SavvyCal, Zcal, TidyCal, Google and Motion. Differentiation is now in (a) preference expression on the booking page (SavvyCal only), (b) dynamic reprioritisation (Reclaim priority-aware links), and (c) manual-but-fast slot offering (Vimcal Slots, Notion snippets).
- "Travel time" as a booking-page constraint is effectively absent from link tools; it lives in AI calendars (Reclaim travel-time events) and remains an open Cal.com location-availability request.
- Meeting batching / adjacency is a recognisable unmet need (Calendly Community #210 years ago; Cal.com #26187 in Dec 2025) that no surveyed tool implements natively; the Cal.com proposal is a ready-made spec (adjacency tolerance, event filter, empty-day rule) for a personal tool.

## KQ2. Which tools let you differentiate by WHO is booking (friends vs clients vs strangers, VIP/per-person links, personalised overrides, single-use links)?

### Takeaway
Differentiation by booker is done almost entirely through links, not identity: single-use links (Calendly, Cal.com private links, Notion one-off links), per-recipient personalised links with full property overrides (SavvyCal), and priority tiers on links (Reclaim). No surveyed tool recognises the booker's identity (e.g. email domain or contact group) and adapts availability automatically.

### Cited Findings
- Calendly single-use links: "The link expires after one successful booking, so it can't be reused or forwarded"; for one-on-one types you can "Personalize meeting name, contact information, duration, location, and availability"; a new link must be created each time — [Calendly Help: create a single-use link](https://calendly.com/help/how-to-create-a-single-use-link); [Calendly blog: single-use links](https://calendly.com/blog/one-time-calendly-link)
- Calendly Community thread "Allowing extra access to certain people" indicates users ask how to give selected people wider availability — [Calendly Community #337](https://community.calendly.com/how-do-i-40/allowing-extra-access-to-certain-people-337) (blocked; title and existence only)
- Cal.com Private Links: "ideal for invite-only sessions, VIP access, pilot programs"; each is "a secure, hash-based URL"; can "automatically expire after it has been used a specific number of times, for example, expires after 2 successful bookings" and/or by date; several private links per event type "each with its own unique usage rules" (Cal.com v5.6 "Advanced private links") — [Cal.com Help: Private Links](https://cal.com/help/event-types/private-links); [Cal.com blog: private links expiration options](https://cal.com/blog/private-links-expirations-options); [Cal.com v5.6 release](https://cal.com/blog/calcom-v5-6); [fix PR #29933 for combined time+usage expiry](https://github.com/calcom/cal.diy/pull/29933)
- SavvyCal personalised links (e.g. savvycal.com/you/john) "allow[] you to customize all properties of the scheduling link for the individual recipient, such as the link title, description, availability settings"; overrides can be scoped "to a specific attendee" — [SavvyCal Docs: Personalizing links](https://docs.savvycal.com/article/14-personalizing-links); [SavvyCal changelog: Override improvements](https://changelog.savvycal.com/override-improvements-319737)
- Reclaim Scheduling Links have priority levels so "you can offer your most availability for important meetings" by exposing lower-priority habits/tasks/meetings as bookable — [Reclaim: Scheduling Links](https://reclaim.ai/features/scheduling-links)
- Vimcal Outstanding Slots keeps "Nicknames to keep tabs on who a Slot was for" — [Vimcal: Calendly alternative](https://www.vimcal.com/calendly-alternative)
- Notion Calendar: "Create recurring link or Create one-off link" — [Notion Help: Scheduling & availability](https://www.notion.com/help/availability-blocking-and-time-zones)
- Motion: preferred times are set per booking link, so different links can carry different preferences — [Motion Help: Availability & Scheduling Rules](https://www.usemotion.com/help/time-management/booking-links/reference-booking-links/availability-and-scheduling-rules)
- Cal.com hidden events + private links explained as the way to keep some event types off the public page — [Cal.com blog: hidden events and private links](https://calcom.framer.website/blog/mastering-cal-com-hidden-events-and-private-links-explained)

### Inferences
- The "who" model in every tool is really "which link did I send", which pushes the burden of classification onto the host at send time. For a personal tool, a cheap upgrade is a link-per-audience (friends / work / strangers) with different schedules, caps and priorities — exactly what SavvyCal personalised links and Reclaim priority links approximate — plus single-use links for one-offs.
- Nothing surveyed supports policy like "people in my contacts can book evenings; strangers only Tue/Thu afternoons" without pre-generating links; identity-aware availability is an open design space.

### Gaps
- Could not read the Calendly Community thread #337 to see whether Calendly staff proposed a workaround.
- Found no evidence of any tool applying availability rules based on booker email domain or CRM segment (absence of evidence, not confirmed absence).

## KQ3. How do tools handle soft-blocked time (tentative, "free" events, focus time, working location, OOO, secondary personal calendars) and the "I'm free but don't book me" problem? What do users complain about?

### Takeaway
All link tools reduce a calendar event to its free/busy flag (Calendly, Cal.com, Google) and treat Outlook tentative/working-elsewhere/away as busy by default, with opt-outs in Calendly; Google's focus-time/OOO/working-location "status events" are only partly interpretable via API and break tools that expect plain busy flags. The practical workaround everyone lands on is either naming conventions on calendar events (SavvyCal time blocks) or an AI layer (Reclaim) that owns the soft blocks and can move them; users complain both ways — tools booking over soft blocks and tools refusing to book over soft blocks.

### Cited Findings
- Calendly (official): "checks your connected calendars for events marked as Busy and treats those as conflicts; events marked as Free are ignored"; for Outlook, default unavailable statuses are "Busy, Tentative, Away/Out of office, and Working elsewhere" — [Calendly Help: Busy vs Free settings](https://calendly.com/help/how-to-manage-busy-vs-free-calendar-settings); [Calendly Community: free/busy status guide](https://community.calendly.com/asked-answered-79/calendly-calendar-availability-and-free-busy-status-guide-4885)
- Calendly (official): Free/busy rules include "Allow invitees to book over selected meetings" (available on the free tier); "Free/Busy rules are not set up by default" — [Calendly Help: Free/busy rules overview](https://help.calendly.com/hc/en-us/articles/20468357687191-Free-busy-rules-overview); [Calendly Community #4878](https://community.calendly.com/how-do-i-40/need-resolution-for-allow-people-to-book-over-events-on-connected-calendars-4878)
- Calendly (user report): an organiser wanted invitees to see "all free spots and all tentative spots" and noted Calendly "used to" offer a "Treat the following as available" checkbox including "Tentative" — [Calendly Community #5867](https://community.calendly.com/how-do-i-40/how-can-i-set-all-outlook-tentative-meetings-so-calendly-thinks-they-are-available-free-5867)
- Calendly (user report): a "Feature Request: Ability to change Google Calendar Invite and have Calendly Recognize" thread exists (details unreadable) — [Calendly Community #3122](https://community.calendly.com/how-do-i-40/feature-request-ability-to-change-google-calendar-invite-and-have-calendly-recognize-3122)
- Google Calendar (user report): "Calendar focus time blocks my calendly calendar" community thread — [Google Calendar Community 168612855](https://support.google.com/calendar/thread/168612855/calendar-focus-time-blocks-my-calendly-calendar?hl=en); users also ask how to mark Focus Time as tentative and for a tentative status between busy and free — [thread 174369764](https://support.google.com/calendar/thread/174369764/how-can-i-mark-an-appointment-or-focus-time-as-tentative?hl=en); [thread 373956293](https://support.google.com/calendar/thread/373956293/tentative-meeting-option-instead-of-busy-or-free?hl=en-GB)

- Cal.com (user reports): OOO events "incorrectly blocking out these times in my consulting service availability", requester wants a setting to treat OOO as non-blocking; opened 8 Jan 2024, still open, "Low priority / Stale", no maintainer reply — [cal.diy issue #13090](https://github.com/calcom/cal.diy/issues/13090). ### Inferences
- The failure mode is symmetric: soft blocks marked "free" (Google all-day OOO, holidays, working location) get booked over; soft blocks marked "busy" (focus time, tentative) block people you *would* accept. A binary flag cannot carry "bookable by some, at a cost".
- The strongest existing patterns for a personal tool are (1) SavvyCal-style tagging (calendar events whose title/colour encodes a bookability class), (2) Reclaim-style priority tiers where higher-priority requests may displace lower-priority soft blocks, and (3) Vimcal/Notion-style holds that self-clean.
- Google's status events are the right primitives for school pickup (recurring OOO 15:15–16:00) and focus time, but consumer/secondary-calendar restrictions ("only on primary calendars, and to some … users") and tool support are inconsistent, so a personal tool should read event titles/colours as well as eventType.

## KQ4. How do AI scheduling assistants (Reclaim, Clockwise, Motion, Skej, Lindy, Howie, Cal.ai, Zoom AI Companion, Gemini in Calendar, Copilot) model preferences, and what do users say about accuracy and trust?

### Takeaway
Two preference models exist: (a) structured goals/priorities the tool optimises against (Reclaim habits with windows and "ideal" times, Clockwise meeting hours + focus-time goals, Motion no-meeting time + per-link preferred times), and (b) free-text preferences interpreted by an LLM/human-in-the-loop email agent (Howie, Skej, Lindy, Gemini "Help me schedule", Copilot). Trust reports are mixed: users value automatic protection but complain when the tool moves fixed events or leaves residue; email agents explicitly rely on human reviewers because, as x.ai found a decade earlier, mistake tolerance in scheduling is very low.

## KQ5. What research or design writing exists on preference-based scheduling (HCI papers, x.ai lessons, maker's schedule, batching)?

### Takeaway
Academic work has argued since 2006 (groupTime, CHI) that calendars should encode *preferences*, not just availability; later work learned preferences from calendar history (NESA, CIKM 2018), studied unrepresented uncertainty in scheduling (Haze, CHI 2022) and LLM-mediated group scheduling with adaptive availability representations (Togedule, 2025). Practitioner essays (Paul Graham's maker's/manager's schedule, Cal Newport's deep work and office hours) supply the rationale for batching and protecting focus time, and are cited directly in user feature requests.

### Cited Findings
- groupTime (Brzozowski et al., CHI 2006, Stanford HCI): "investigates using a calendar to represent user preferences rather than availability" and studied how people negotiate by "enumerating available times or describing constraints" in email threads — [groupTime CHI 2006 PDF](https://hci.stanford.edu/publications/2006/groupTime/groupTimeCHI2006.pdf)
- NESA (Kim et al., CIKM 2018): learns "user preferences and … calendar contexts directly from raw online calendars" using >593K events; four jointly-trained layers (title, intention, context, output); "significantly outperforms previous baseline models" on personal and multi-attendee scheduling; code public — [ACM DL: NESA](https://dl.acm.org/doi/10.1145/3269206.3271712); [arXiv 1809.01316](https://arxiv.org/abs/1809.01316); [GitHub dmis-lab/nesa](https://github.com/dmis-lab/nesa)
- "Turning personal calendars into scheduling assistants" (CHI EA 2012): proposes "new entity types that go beyond simple events to better represent human intentions, plans, and goals" — [ACM DL](https://dl.acm.org/doi/10.1145/2212776.2223854)
- Haze (Bowler, Bach, Pschetz, CHI 2022): digital calendars "leave little space to communicate uncertainty regarding time, place, or the ability to attend"; certainty narratives marginalise "people with health conditions or caring responsibilities"; two studies with 21 participants found people "cover up their experiences of uncertainty" — [ACM DL: Exploring Uncertainty in Digital Scheduling](https://dl.acm.org/doi/10.1145/3491102.3502107); [Edinburgh Research Explorer](https://www.research.ed.ac.uk/en/publications/exploring-uncertainty-in-digital-scheduling-and-the-wider-implica/)
- Togedule (2025): "Scheduling Meetings with Large Language Models and Adaptive Representations of Group Availability" — [arXiv 2505.01000](https://arxiv.org/pdf/2505.01000) (abstract not readable; title only)
- "Calendar Horizon as a Boundary Affordance" (eye-tracking study of how much time is visible affects scheduling outcomes) — [PMC13010615](https://pmc.ncbi.nlm.nih.gov/articles/PMC13010615/)
- Negotiation-strategy modelling for meeting scheduling agents — [ResearchGate: Selecting Negotiation Strategies for Meeting Scheduling](https://www.researchgate.net/publication/271891369_Selecting_Negotiation_Strategies_for_Meeting_Scheduling_Using_a_Model_Based_Approach); intelligent calendar assistant scheduling events and tasks (Refanidis & Yorke-Smith) — [Semantic Scholar](https://www.semanticscholar.org/paper/On-Scheduling-Events-and-Tasks-by-an-Intelligent-Refanidis-Yorke-Smith/a02748fcfb2e1ca71c242aca1406d34f75953ab6)
- Paul Graham, "Maker's Schedule, Manager's Schedule" (July 2009) — [paulgraham.com](https://paulgraham.com/makersschedule.html) (text unreadable here; see Gaps for the specific claims not verified)
- Cal Newport: "deep work" defined as "giving something intense concentration without distraction for long periods of time"; uses "busyness buffers (e.g. office hours)"; institutions have implemented "Meeting-free Morning[s]" citing Deep Work — [Fortune, 22 Jan 2016](https://www.fortune.com/2016/01/22/deep-work-focus-distractions); [Liberty University library case](https://digitalcommons.liberty.edu/lib_fac_pubs/216); [A Pragmatic Mind: Deep Work in an open office](https://www.apragmaticmind.com/blog/deep-work-open-office)
- x.ai design lesson (Diane Kim interview): the agents "will only schedule meetings, nothing more or less"; the system lacked logic for conditional availability statements — [Chatbots Magazine](https://chatbotsmagazine.com/amy-and-andrew-ingram-your-ai-assistants-from-x-ai-d350f5f58e43)
- Reclaim's own framing of focus time benchmarks — [Reclaim blog: What is Focus Time](https://reclaim.ai/blog/what-is-focus-time)

### Inferences
- The literature's consistent recommendation — represent graded preference (and even uncertainty) rather than binary availability — is exactly what SavvyCal's ranked schedules and Reclaim's priorities partially operationalise, and what Calendly/Cal.com/Google still lack.
- Haze's finding that carers hide uncertainty is directly relevant to the school-pickup case: a personal tool should let a 3.30pm hard stop and a "probably free after 4.15 but don't count on it" band be first-class states.

- No dedicated x.ai post-mortem document was found; only interviews/reviews.

### Inferences
- For a personal tool serving a busy parent with a 3.30pm pickup, focus-time goals and three audiences, the useful features nobody bundles are: (1) audience-specific policies (friends may book evenings/weekends; strangers only batched afternoon windows on days that already have meetings), (2) an adjacency/batching rule with empty-day behaviour per audience, (3) graded calendar states read from event title/colour/eventType (hard OOO for pickup; soft "focus" displaceable only by high-priority requests; personal-calendar events counted as busy), (4) explicit explanation of *why* a slot is hidden (the debugging pain above), and (5) per-request one-time overrides (single-use link with widened hours) rather than editing the standing schedule.
- Because vendors have left these open for 2–3 years as "low priority / stale", they are unlikely to arrive in the mainstream products soon; building them personally is reasonable.
